# CompatLab v0.2 design

The user's v0.2 specification is the authority. Expand independently authored host compatibility modules only; never access the private runtime. MIT, existing tests and sandbox protections stay intact. Host synthetic tests do not establish Windows EXE or Android success.

## Boundaries
Keep `FileApi` and its target intact. Add a separate C++17 `RegistryApi` target accepting UTF-16 names, host-owned byte buffers and context-owned opaque handles. No ABI/guest memory/Android dependencies. Registry state is in memory per instance, with HKCU writable and HKLM read-only by default; an explicit configuration allows writable **virtual** HKLM for installer profiles. No real system registry access and no persistence in this release.

## Behavior
File changes address creation disposition success metadata, read-only access, CRT mode validation, negative seeks and virtual cross-drive rename. Keep conservative path rejection and ASCII-only case folding; exact Korean/supplementary filenames remain supported. Preserve originals on rejected destructive operations.

Registry implements only open/create/query/set/close initially. Support REG_SZ/EXPAND_SZ as raw UTF-16LE bytes and DWORD/QWORD/BINARY as exact bytes; query uses byte counts and ERROR_MORE_DATA without partial copy. Do not expand strings or silently add terminators. Default value is the empty name. ASCII-insensitive key/value names; exact non-ASCII names supported, full Unicode folding explicitly limited. Handle rights gate query/set, hive policy gates opening/creating. Unsupported options/views/types fail explicitly. Predefined hives are constants; allocated handles are unique across contexts and stale handles fail.

PE analysis retains legacy DLL lists, adds a versioned per-API contract, status-aware static-import frequency and per-input anonymous comparisons. No executable upload or execution, no runtime claims. Four host profiles compose file, registry and CRT behavior.

## Verification and delivery
Record baseline; add failing regressions before code. Run GCC and Clang where available, CTest/Python, ASan/UBSan and repeated resource/isolated-context tests. One public push triggers one workflow with compiler/sanitizer matrix; inspect actual jobs. Update API limitations, adapter contract, roadmap and evidence. Commit/push main is explicitly authorized by the user; no reset/force-push or private access.
