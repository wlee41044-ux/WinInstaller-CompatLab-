# CompatLab v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Tested, isolated file and registry compatibility with honest static coverage reporting.
**Architecture:** Keep FileApi intact; separate in-memory RegistryApi; synthetic host profiles compose both. Private adapters own ABI and guest memory.
**Tech Stack:** C++17/POSIX, Python standard library, CMake/CTest, public Ubuntu Actions.
**Spec:** docs/superpowers/specs/2026-10-14-v02-design.md (and user v0.2 request).

## Global Constraints
- Public repository only; preserve MIT and baseline tests; no reset/force push.
- No guest pointers, x64 engine, Android dependency, APK or performance work.
- Errors must be explicit; paths stay within designated virtual drives.
- No real EXE execution success claims; host fixtures only.

## Review Focus
- Destructive failure: original bytes survive sharing/read-only/mode rejection.
- Cross-context and stale handles: cannot access another context's registry.
- Size negotiation: bytes, no overrun or implicit string termination/expansion.
- Invalid PE fields: no reading unbacked bytes or fabricated supported status.
- Repeated open/close: stable OS descriptor and registry live-handle counts.
